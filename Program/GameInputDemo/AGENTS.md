# GameInputDemo

Follow the rules for GUI programs in the [AGENTS.md](../../AGENTS.md) at the root, including the supported window setups and the non-disruptive workflow. Run the demo with `Program\RunInBackground\RunInBackground.ps1 GameInputDemo`.

- The demo is a `Program` of [Library/UserInterface](../../Library/UserInterface/README.md), in `Source/Demo.rs`, which `user_interface::run` runs. `Source/Cards.rs` draws the cards with the library's app bar, status bar, cards, combo box, list view, scroll areas, keycaps, badges, status icons and tooltips, in the theme's roles and with the tokens, and draws the rest, like the stick graphs, the trigger bars and the button chips, with `ui.painter()`.
- The demo reads gamepads itself, with GameInput, so its `Options::gamepad` is off, and it drops GameInput's readings while `ui.window_focused()` is false. It reads its shortcuts `F1` and `F2` with GameInput. `F11` is the library's, from the window's messages, so the demo must not also switch fullscreen on GameInput's `F11`. `Demo::update` calls `ui.set_focusable(false)`, so that no widget takes keyboard focus, and the keys stay the user's, to try the Keyboard card with.
- `Source/Cards.rs` has the layout's constants. Of the 71 pixels that borderless fullscreen adds to the height, the bottom row of cards and the event log get all of them.
- Test input handling with the tests and scripts in `Test/GameInputDemo`, as the [README](README.md#testing) says. Scripts connect gamepads, keyboards and mice, and give their readings, with `Program` steps, which `Demo`'s `Program::script` hands to `Source/ScriptedSource.rs`. The state that scripts save has the interface's, as `Interface`: the combo box, `Gamepad`, its choices, `Gamepad/0` and on, the Devices card's list, `Devices`, and its rows in sight, `Devices/0` and on, with their devices' labels, as `Targets`, whether the combo box's list is open, as `Popup`, and which row's tooltip shows, as `Tooltip`. Steps point at them by name.
- Keep GameInput's calls in `Source/GameInputSource.rs`, so that the rest of the demo runs on scripted input too. Ask the user to try what only real devices show, like GameInput's own readings and the motors.
