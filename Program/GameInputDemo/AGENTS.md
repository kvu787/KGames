# GameInputDemo

Follow the rules for GUI programs in the [AGENTS.md](../../AGENTS.md) at the root, including the supported window setups and the non-disruptive workflow. Run the demo with `Program\RunInBackground\RunInBackground.ps1 GameInputDemo`.

- The demo is a `Program` of [Library/UserInterface](../../Library/UserInterface/README.md), in `Demo.h`, which `user_interface::run` runs. `Cards.cpp` describes the cards with the library's app bar, status bar, cards, combo box, list view, scroll areas, keycaps, badges, status icons and tooltips, in the theme's roles and with the tokens, and draws the rest, like the stick graphs, the trigger bars and the button chips, with `Canvas`.
- The demo reads every device's readings from the library's `startup.devices`, which the library reads with GameInput once a frame, and it drops them while `ui.window_focused()` is false. It reads its shortcuts `F1` and `F2` from those readings. `F9`, `F10` and `F11` are the library's, from the same readings, so the demo must not also switch the theme on `F9`, vertical sync on `F10` or fullscreen on `F11`. `view`, in `Cards.cpp`, calls `tree.set_focusable(false)`, so that no widget takes keyboard focus, and the keys stay the user's, to try the Keyboard card with.
- `Cards.h` and `Cards.cpp` have the layout's constants. Of the 71 pixels that borderless fullscreen adds to the height, the bottom row of cards and the event log get all of them.
- Test input handling with the tests and scripts in `Test/GameInputDemo`, as the [README](README.md#testing) says. Scripts connect gamepads, keyboards and mice, and give their readings, with `Program` steps, which `Demo::script` hands to `ScriptedSource`, in `ScriptedSource.h`. The state that scripts save has the interface's, as `Interface`: the combo box, `Gamepad`, its choices, `Gamepad/0` and on, the Devices card's list, `Devices`, and its rows in sight, `Devices/0` and on, with their devices' labels, as `Targets`, whether the combo box's list is open, as `Popup`, and which row's tooltip shows, as `Tooltip`. Steps point at them by name.
- Keep what the demo takes from the library's devices in `GameInputSource.h` and `GameInputSource.cpp`, so that the rest of the demo runs on scripted input too. Ask the user to try what only real devices show, like GameInput's own readings and the motors.
