# GameInputDemo

Follow the rules for GUI programs in the [AGENTS.md](../../AGENTS.md) at the root, including the supported window setup and the non-disruptive workflow. Run the demo with `Program\RunInBackground\RunInBackground.ps1 GameInputDemo`.

- The demo is a `Program` of [Library/UserInterface](../../Library/UserInterface/README.md), in `src/demo.rs`, which `user_interface::run` runs. `src/cards.rs` describes the cards with the library's app bar, status bar, cards, combo box, list view, scroll areas, keycaps, badges, status icons and tooltips, in the theme's roles and with the tokens, and draws the rest, like the stick graphs, the trigger bars and the button chips, with `Canvas`.
- The demo reads every device's readings from the library's `startup.devices`, which the library reads with GameInput once a frame, and it drops those that came without focus, putting the window's focus changes, which the library's devices give on the readings' clock, among them by their times. It reads its shortcuts `F1` and `F2` from those readings. `F9` and `F10` are the library's, from the same readings, so the demo must not also switch the theme on `F9` or vertical sync on `F10`. The demo has no text field, the only widget that takes keyboard focus, so the keys stay the user's, to try the Keyboard card with.
- `src/cards.rs` has the layout's constants. The bottom row of cards and the event log get what's left of the window's height.
- Test input handling with the tests and scripts in `Test/GameInputDemo`, as the [README](README.md#testing) says. Scripts connect gamepads, keyboards and mice, and give their readings, with `Program` steps, which `Demo`'s `Program::script` hands to `src/scripted_source.rs`. The state that scripts save has the interface's, as `Interface`: the combo box, `Gamepad`, its choices, `Gamepad/0` and on, the Devices card's list, `Devices`, and its rows in sight, `Devices/0` and on, with their devices' labels, as `Targets`, whether the combo box's list is open, as `Popup`, and which row's tooltip shows, as `Tooltip`. Steps point at them by name.
- Keep what the demo takes from the library's devices in `src/game_input_source.rs`, so that the rest of the demo runs on scripted input too. Ask the user to try what only real devices show, like GameInput's own readings and the motors.
