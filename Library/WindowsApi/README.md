# WindowsApi

The Windows API bindings that every Rust package in KGames uses, in one crate, so that a
type like `HWND` or `ID3D12Device` is the same type in all of them.

The bindings in `Source/Bindings.rs` are generated by
[`windows-bindgen`](https://crates.io/crates/windows-bindgen) and committed, so normal builds
don't compile the generator. Their only dependency is Microsoft's
[`windows-core`](https://crates.io/crates/windows-core) crate.

## Using more APIs

1. Add the API's native name to `BindingsGenerator/Filters.txt`.
   For a method that an interface inherits, name the base interface, like `IDXGISwapChain::Present`.
2. Regenerate `Source/Bindings.rs` from this folder:

   ```powershell
   cargo run --manifest-path BindingsGenerator/Cargo.toml
   ```

3. Commit `Filters.txt` and `Bindings.rs` together.

GameInput isn't in the Windows metadata that `windows-bindgen` reads, so its bindings are
written by hand in [Library/GameInput](../GameInput/README.md) instead.

## Layout

| Path                               | Contents                                                       |
| ---------------------------------- | -------------------------------------------------------------- |
| `Source/Library.rs`                | Exports the bindings                                           |
| `Source/Bindings.rs`               | Generated Windows API bindings; don't edit by hand             |
| `BindingsGenerator/Filters.txt`    | The Windows APIs to generate bindings for                      |
| `BindingsGenerator/Source/Main.rs` | Runs `windows-bindgen` to write `Source/Bindings.rs`           |
